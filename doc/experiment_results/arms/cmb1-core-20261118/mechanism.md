# 属性核心臂（cmb1-core-20261118）记忆机制

1. **引擎持有身份**：属性注册表为每个（实体, 规范化槽位名）分配稳定 `property_id`；身份键 = 实体 + property_id + scope。模型只提交槽位名，不再决定身份键；同一属性的不同表面写法只有在显式别名后才合并。
2. **状态 / 事件分流**：`kind=state` 的属性在实体作用域就地更新，新修订覆盖当前投影；`kind=event` 的属性（建议/提醒/约定/事项等泛称，以及状态/情况/感受等快照）按 `event:<来源事件>:<值摘要>` 建立独立身份，两次不同观察永远不会互相覆盖。
3. **无写时 pending / 关系 / 树 / 向量**：无法绑定的观察直接作为事件观察落库，不阻塞写入；`consolidate()` 只做属性回填和一致性审计；旧库打开时自动补列，`rebuild()` 重建投影与索引。
4. **检索**：每个修订写入倒排词项索引（词频，按不同修订数平均，避免长寿属性因修订多而虚高）；as-of 检索覆盖所有修订，因此能命中已被覆盖的旧值；与实体锚点查询做秩融合。时间选择只认 `valid_from`，`recorded_at` 只作审计。
5. **证据与冲突**：检索结果携带来源事件原文（每源最多 700 字），适配器渲染每行最多 400 字原文；冲突不做隐式消解，历史观察全部保留，由 as-of 时间选择决定“当时”的值。
6. **遗忘**：无删除、无 closed 状态切换路径，只有修订、头和投影；存储增长主要来自按修订建立的倒排索引。
