# 状态修复臂（pmx-sf-20261121）

1. **需求综合改为跨区间**：`engineState` 从累计控制原文（journal 的 40 条请求）生成需求，而不是只看当前遮蔽区间的 user 行；这与参考实现从全事件投影的做法一致。
2. **未匹配的最新请求变成 `next`**：需求在本区间没有对应编辑时，旧逻辑直接丢弃；现在最新一条会写入 `Next`，检查点不再出现空的 Current state/Next step。
3. **最近变更块**：`Recent changes` 列出最近 3 个不同路径的编辑（路径、edit/check 序号、改动首行），位于状态块之后、机械校验之前。
4. **最新请求横幅**：控制原文超过 4 条时，在片段顶部重述一次最新请求（最多 240 字），避免最新指令被 40 条历史请求淹没。
5. **警告阈值保持 0.6**：本臂用于隔离“状态/最近变更”与“警告阈值”两个因素；探针轮仍可能在 60–80% 区间收到压力提示，产生额外一步。
