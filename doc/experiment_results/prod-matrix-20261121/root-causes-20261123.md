# 三个残余问题的根因与修复（2026-11-23）

对象：`dsh-wsc` nosig 引擎在 `experiments/prod-matrix` 60 次真实会话（616 个检查点）中暴露的三类问题：抽取提示、值列表噪声、单次成本波动。所有数字来自 `experiments/prod-matrix/summary.csv`、各会话的 `compaction/summary` 与 `$DSH_HOME/wsc/nosig/<session>.jsonl`，可重跑复核。

## 0. 先修正成本口径

矩阵的主成本只累加 `status/step_end` 的 usage；WSC 的抽取调用和原生压缩调用都不在这个事件里。

- 引擎现在每次抽取后写一行 `op:"usage"` 到 nosig journal。实测：`feature-25/w80` 每次抽取约 1.17 万输入 + 0.2 万输出 token，¥0.020/次（rep5 4 次共 ¥0.080）；`long-40/w80/rep4` 21 次共 ¥0.419。
- 原生压缩同样是独立模型调用，会话事件里没有 usage。用 `shadowedTokenCount × ¥1/M + 摘要字符/4 × ¥4/M` 估算：`feature-25` 约 ¥0.135/次运行，`long-40` 约 ¥0.54/次运行。

据此重算中位数：

| 场景 | 原生主成本 + 压缩估算 | WSC 主成本 + 抽取 | 全成本比 |
|---|---:|---:|---:|
| feature-25 | 0.247 + 0.135 = **0.38** | rep5 0.133 + 0.080 = **0.21**（rep4 0.26） | 0.56–0.69× |
| long-40 | 0.816 + 0.536 = **1.35** | rep5 0.371 + 0.356 = **0.73**（rep4 0.85） | 0.54–0.63× |

结论方向不变，但此前只算主循环的 0.47×/0.65× 低估了两边的压缩开销；对外应引用 **0.54–0.69×**，并注明压缩侧是实测（WSC）与估算（原生）。

## 1. 抽取偶尔失败

**现象**：616 个检查点中 408 个（66.2%）带 `## Extraction gaps`。按行归类：

| 行 | 次数 | 含义 |
|---|---:|---|
| `region: N entries rejected` | 369 | 部分条目被拒，其余已写入 |
| `did not finish`（含 error） | 30 | 抽取调用未完成（网关 429、截断等） |
| `unknown-ref` / `literal-not-in-cite` | 13 / 9 | 新日志已带原因 |
| `no JSON object after retry` | 4 | 模型两次都回非 JSON |
| `no extractable entries` | 2 | 空结果，本不是失败 |

**根因**（四层，按占比）：

1. **引用索引漂移**：模型抄对了字面值，但 `cites` 指到了相邻消息，`literal` 校验要求字面量出现在被引用消息内，于是整条被拒。条目本身是真的，只是来源标错。
2. **修订引用过期**：`revise` 的 ref 指向旧版本或本轮之前已被截断的条目；`prior` 只渲染 4000 字节账本，长会话里较早的条目根本不在模型眼前，`revise` 只能猜 ref。
3. **一次失败即整段丢失**：原实现只在「非 JSON」时重试；流错误、`finish=length`（输出预算被推理 token 占满）直接返回 gap。
4. **披露过宽**：只要有 1 条被拒就写 gap 行；「空结果」也写 gap，导致 2/3 的检查点看起来像抽取失败。

**修复**（`lib/nosig.js`、`engine.js`）：

- **重定位引用**：当字面量不在被引用消息里，但在区间其他消息里逐字存在时，改用命中的消息号；只允许标识符、路径、小数等强锚点参与重定位，纯整数（如 `20`）不允许，避免把不相干的行拉进来。新增 `recovered` 计数。
- **未知 ref 转新增**：ref 指向不存在的条目时，校验通过的文本作为新条目写入；若账本已有同文条目则静默跳过。只有「ref 指向存在但已过期」仍拒绝（`stale-ref`），避免把已推翻的旧关系复活。新增 `converted` 计数。
- **重试覆盖所有失败**：调用抛错也重试一次；`finish=length` 时第二次要求「最多 3 条、每条 120 字符、无解释」。abort 不重试。
- **prior 账本 4KB → 8KB**：与 passage 的 8KB 预算一致，长会话的 ref 可见性提高；每次多约 1k 输入 token（¥0.001）。
- **空结果不再报 gap**；只有真正被拒/未完成才披露。

**验证**：`feature-25/w80` 修复前 4 次运行共 12/21 个检查点带 gap；修复后 rep5 为新代码完整运行，**0/4**，严格探针 5/5，测试 20/20，抽取成本 ¥0.080。`feature-25/off` rep2 同样 0/4。`long-40/w80` 修复前 4 次为 11/20、16/28、21/25、14/21；修复后 rep5 为 **0/18**，严格探针 5/6（第 6 条错答），测试 36/36。全量 `npm test` 228 项通过。

**残余**：连续两次调用失败、或字面量在整个区间确实不存在时仍会记 gap；高并发（4 路）下的 429 仍可能吃掉两次机会。这两类不会写错记忆，只丢当轮可抽取内容。

## 2. 值列表噪声

**现象**：60 次会话、616 个检查点累计渲染 14,584 条 `[V<n>]`。按标签分类：

| 类别 | 条数 | 占比 |
|---|---:|---:|
| 文件快照的首行（`path: 1: ...`） | 6,183 | 42.4% |
| 测试文件行 | 5,288 | 36.3% |
| spill / 临时路径 | 784 | 5.4% |
| JSON 载荷 | 229 | 1.6% |
| 其他 | 2,042 | 14.0% |
| 真正的常量赋值 | 2 | 0.01% |

长程 `w80/rep1` 的末次检查点最新值就是一条 `dsh-spill` 路径，`TAX_RATE = 0.07` 被淹没。

**根因**：旧 `valueRows` 把任意工具结果中的数字/错误信号都当成「值」。`read` 的结果是一个带行号的完整文件快照，于是文件里的每个数字、测试断言、临时路径都进入账本；而且每个区间都会重新发现，列表只增不减。

**修复**（`lib/values.js`、`lib/nosig.js`）：

- 只从 `read` 且目标不是 `tests/`、`node_modules`、`dist`、`fixtures`、`dsh-spill`、锁文件的路径提取；
- 只接受三种数值赋值行：`const/let/var NAME = <number>`、`NAME = <number>`、`"name": <number>`；
- 以 `路径#变量名` 为身份去重，同一常量被重读时保留原来的 `V` 键、更新值和序号，不再产生互相矛盾的两行；
- `pwsh`、`grep` 结果不再产生值。

**验证**：把同样规则离线回放到 3 个真实会话，126/148/46 次文件读取分别蒸馏出 **3/3/2** 个常量（`TAX_RATE=0.07`、`DEFAULT_TAX_RATE=0.07`、`DEFAULT_REPORT_LIMIT=20`），噪声下降 >99%。`feature-25/w80/rep5` 的末次检查点值区只有一行：`[V1] src/store.js: TAX_RATE = 0.07`；`long-40/w80/rep5` 为 3 行。零模型调用，值区字节数同时下降。

## 3. 单次波动大

**现象**：`long-40/sf` 有一次 ¥0.571、40 次压缩；同场景 `w80` 为 ¥0.386–0.492、20–28 次。60 次运行的相关系数：**压缩次数 vs 输出 token = 0.978**，vs 步骤数 = 0.931。

**根因**：

- 压缩次数不是引擎抖动，而是**同一份工作的token 体量**。这次运行的 207 次读文件中，`report.js` 39 次、`report.test.mjs` 33 次、`cli.js` 24 次；对照 `w80/rep1` 共 126 次读、`native/rep1` 123 次（原生同样反复读 `report.test.mjs` 24 次）。模型在每轮重新确认文件状态，读得越多、上下文涨得越快、压缩越频繁。
- `sf` 臂的 `warnRatio=0.6` 让压缩更早发生，把一次工作放大成更多次抽取调用（每次 ¥0.02），所以同一任务的压缩数 21–40，而 `w80` 为 20–28。
- 采样本身有方差：同一臂的多次运行成本可差 2×。这是模型/工具循环的属性，不是 passage 的 bug。

**处理**：

- 生产 `warnRatio` 已改为 0.8（与 force 同级），避免 60% 提示额外多一回合；桌面 profile 需重启加载。
- 所有对照改为**同场景、同日、看中位数**，单次只当样本；本报告新增的抽取成本也进入总成本，不再只比主循环。
- 不针对单次异常调引擎阈值。`sf` 的 21/31/40 次压缩恰好证明：把 warn 提前只会增加压缩与抽取次数，不会降低总成本。

## 口径修正（2026-11-23 晚）

关键词探针把“用户提示里出现过”当成“回答正确”，把工具结果里的事实也算进 haystack；现已改为只读 final 回答并支持 `must/forbid`。重打分后：long-40 native rep1 6/6、rep2 5/6，w80 rep5 5/6；多个长程臂末轮只回“已压缩，等待指令”，旧口径记 6/6，新口径为 0/6。feature-25 仍为 5/5。

## 残余与下一步

- `long-40/w80/rep5` 已用修复后代码完整重跑：18 次压缩、0/18 gap、值区 3 个常量、总成本 ¥0.726（rep4 0.854）。
- 抽取关闭推理的初步结果：`feature-25/off` 两次总成本 ¥0.256 / ¥0.222，抽取输出 1.5–1.8k/次（默认约 2.0–2.1k/次），探针 5/5，修复后一次 0/4 gap。样本仍少，暂不改生产默认。
- 原生压缩 usage 仍未直接采集；当前只用 shadowed token 与摘要长度估算，若要把全成本写进对外结论，应在原生侧也落 usage。
