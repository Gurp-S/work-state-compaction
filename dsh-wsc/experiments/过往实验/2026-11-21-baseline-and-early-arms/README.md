# 2026-11-21 早期矩阵：wsc / cap / fix / sf / old / off 对 native

问题：WSC 的逐字控制、工作集合并与状态块，在 16–25 轮脚本任务上是否值得成本。

- `wsc`：quotes + workingset v2 + denoise。
- `cap`：再加 `controlMaxBytes: 6000`（逐字控制预算）。
- `fix`：`cap` + `passageWorkingset: true`。
- `sf`：`wsc` 去掉 work set 的对照。
- `old`：关闭 `stateFromControls`、`passageRecent`、`passageLatest`（旧投影）。
- `off`：`nosigReasoningEffort: off`。
- `native`：dsh 原生 `compaction-basic`，作为质量/成本基线。

本场没有留下逐轮日志，只有 summary 行；11-16 的 B 组 A/B 完整 profile 放在 `profiles/`。

裁定：这一批只用于定位方向，样本少且场景短；长跑结论以下一个营为准。工作集不降低读取，`cap` 没有稳定收益，最终被 11-23 的 quotes/ledger 方案取代。
