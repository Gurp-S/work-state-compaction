# 两轮压缩后的旧信息恢复：三对系统观测完成

2026-10-27。B 为未修改原生压缩；C 为 WSC compact wire + 来源工具 + 精简选择器。三个重复使用同一预定义历史和同题程序评分，无额外 LLM 裁判。**未压缩 6/6，B 3/6，C 6/6。C 的完成链路平均调用 Token 比 B 多 5.4%，阶段耗时多 39.6%。**

这是一个具体的主要目标收益：两次压缩之后，系统仍能找回并利用早期观察完成当前查询。它不是所有长期任务的保证，也没有证明平均更省、更快。

## 公平性与复用边界

这组是**历史复用与新增运行混合的三对系统观测**，并非全部前瞻、完全同 revision 的随机对照：

- 原三次 B1/B2 和 C1 已完成，原始事件顺序/来源/模型和 effort 固定，不重复开发或压缩。每对都是相同原业务流，查询在独立兄弟分支进行，不污染压缩主干。
- R02 C 复用上一轮完成结果；R03 B 复用前轮完成的一次后测，均未碰其旧 2 响应预算。后续 B/C 查询上限统一为 4 响应、120000 Token、120 秒；历史一次响应的结果在较大的非约束预算下保留，不反向修改旧登记。
- R03 C 本轮选材已经完整结束、完成导入，但被其他分支的 unknown 冻结了查询。校验生成 transcript、绑定、完整导入、冷资源和未污染父线程后，**仅补一次答题**，没有再次选材。
- R01 C 使用下面的新预算错误结果旁路；R02/R03 C 使用旧 handler。但三条最终接受的 C trace 都只调用一次来源工具，未触发修复分支。报告程序对这三条真实请求分别用旧/新 handler 零模型回放，结果逐字节一致，源数据库不变。这支持本组已执行路径的兼容性，不能推断所有可能轨迹都等价，也不将它写成所有 C 完全同版本。
- B 的正常工具/恢复能力保留，未人为喂入原始冷存储或 WSC 工具。C 允许其正常来源读取。故比较为系统级，不是严格算法级等资源实验。内部压缩模型/参数、内部上下文与持久化成本未知；actor 同为固定本机二进制、gpt-6-luna、effort=max，模型随机性和共享缓存/服务干扰仍在。

已观测的每对准确率差都是 +0.5，但三次同一案例的描述性 bootstrap 会退化为零宽区间，不能当总体置信保证。完成链路 Token 差异的描述性区间包含正负值；不能从一个较省的 R02 推断一般费用优势。

Pareto：本组平均 C 质量更高、平均调用 Token 也更高，两点互不支配；R02 单对 C 正确更多且调用更少，只是局部观测。没有等热上下文 Token 曲线、金额优势或长期 5/10/20/50 次压缩稳定性证明。

## 实测暴露的协议缺陷及修复

`wsc-minimal-recovery-group-20261027-v4` 的 R01 实际读了八个旧来源，其中包括目标 s6。第九个合法绑定回调触发 `source_tool_callback_budget_exhausted`。旧 handler 在错误适配层外抛异常，导致整个选择 turn 被中断，进而冻结研究账目。它已经得到目标文本，却不能提交后续选择，这个失败不能归咎于“没存住 nonce”。

结构性根因：执行层资源拒绝越过工具结果协议，变成宿主会话异常。结构规则：合法绑定的资源超限返回中性错误结果；访问上限与身份边界仍硬执行。回归覆盖：第九个请求不再中断、读次数始终八、先前八次返回与旧版相同、重复回调幂等、跨 turn/身份冲突仍拒绝、千次拒绝不增长缓存/trace。

新独立 `native_source_tool_budget.BudgetResultSourceToolHandler` 只适配这一种已验证的预 I/O 资源错误，不吞其他异常，不扩大权限，不增加读取次数，不提示模型应选什么。旧 handler 保留，新版由 `--budget-tool-results` 显式启用，策略尾缀 `/budget_results_v1`，不默改所有宿主。

真实失败的九个回调零模型前后回放：旧版第九次抛异常；新版前八次严格相同，第九次 `success=false` / `status=error` / 原错误码；两者各读八次。原 DB hash 不变。证据 `wsc-source-budget-replay-20261027-v1`。

R01 新资格实测 2/2、61890 Token / 3 响应，只调用一次 find。**这次未触发超限，不能说“修复让模型在第九次错误后成功续接”**；确定性回放证明协议分支，真实调用证明新旁路的正常路径与 QA。泛化到超限后模型选择是否合理仍须另测。

新增 `qualify_budget_results.py`、`resume_published_c_query.py`、`resume_native_recovery_queries.py` 分别只做受登记约束的新修复资格、已发布 C 答题、缺失 B 后测；不再整体重跑失败组。`minimal_recovery_report.py` 独立重算精确答案、阶段回执、全链成本、去重 response_id 与兼容性回放，生成 JSON/CSV/图。
