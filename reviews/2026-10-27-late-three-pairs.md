# 晚位恢复三组系统对照：正确性收益与成本

三组相同案例的字段结果一致：未压缩 U 6/6、原生 B 3/6、WSC C 6/6。B 每次均正确回答当前构建号，未正确恢复 build-270 原始 nonce；C 每次两项正确。完整逻辑链调用 Token 平均 B 126612.7、C 188466.7，C 多 48.85%。本例支持“WSC 正常持久化恢复帮助完成晚位历史查询”的有限系统证据，不支持“更省、更快、普遍超越原生”。

## 实验边界

同 seed=20261028 的 320 构建历史、目标来源 s540、两次压缩/选材边界、同两问题、同 gpt-6-luna/max、同可执行文件及权限。后测统一 120000 Token/4 响应/120 秒。源 DB、C1、原 parent 封存不变。Ground Truth 由数据生成器产生，类型和精确字段比较，不以关键词计分，无额外 LLM 裁判。

R01 是历史 C 与后补 B/U；R02/R03 为本轮新运行。三个 C 共享已完成的 C1，重复的是固定 C1 后的 C2 选材与查询；三个 B 各自真实执行两次原生压缩。不能称为三条独立完整模型选材链，更不能称为三个不同任务。初始公开前缀和未压缩全文与封存 parent 校验一致，只有既有传输标识/metadata 标准化，业务文本不变。

R02/R03 每组固定三个 worker 并行 B/U/C，两组顺序执行，提交顺序 B/U/C 与 C/U/B。新 C 启用经过等价验证的函数绑定复用和主机计时，模型输入表示、schema、语义选择及资源检查保持；每个 C 从新 cold-public/cold-objects 开始，与原资格轮同为冷制品环境。操作系统缓存、服务队列、网络和内部压缩参数不受控，提交顺序也不保证服务端实际执行顺序。不是局部性能优化的随机因果实验。

## 审计问题及修复

原来源工具审计器只扫描对象/数组括号，R03 模型将正常工具结果再次 JSON 编码为字符串，导致原扫描器无法还原转义引号。它报匹配失败，而不是实验工具丢失了数据。

规则：对完整合法 JSON 字符串做有界严格解码，不猜测转义、不修改字段值、不接受近似匹配。新增 `structured_tool_outputs.py` 仅用于离线审计，`audit(..., decode_json_strings=True)` 显式开启，旧默认不变，评分器不改。新扫描后四条真实输出均与主机 trace 和源范围/hash 精确匹配；R02 一条也通过。正反例 3 项通过，包含双重编码、错误值不修补、非法 JSON 不猜测。旧审计失败保存在 `report-audit-attempt-v1-failure.json`，为观察失败后的补记，精确时间 unknown；没有重跑任何模型。

报告检查全部新 17 个唯一 response ID、各臂和全局账本，所有关闭日志的回执集合与阶段一致；六次 B 原生压缩均有持久边界/绑定回执/terminal 确认，U 三组本地没有压缩事件；C 两个新请求与旧协议等价、实际工具输出与来源相同；原 source 和全部拥有进程清理通过。没有检查或解密原生摘要内容。
