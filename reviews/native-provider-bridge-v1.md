# 受控原生通信通道 v1

2026-10-30。独立旁路，默认链路不启用；真实模型调用 0，不是新 B/C 实验。

## 职责与边界

隔离环境内部的 Python HTTP 入口只接受 POST /v1/responses，通过本轮专用 Unix socket 和外部 worker 的宿主标准输入输出交换数据。宿主 ProviderGate 固定模型、路由、请求次数、体积和派发截止时间；宿主回调负责真实认证、固定提供方、实际调用超时与用量核算。本模块没有凭据加载器、任意 URL 转发、文件读取 RPC、CONNECT 或自动重试。

只增加本轮随机 socket 目录的只读挂载，原闭集文件系统、独立 PID/网络命名空间和 UID 65534 保留。没有开放宿主网络或挂载用户主目录。入口只在隔离命名空间的 127.0.0.1 监听，原生二进制未修改，提供方配置仅存在于该子进程的启动参数。

新模块：native_provider_frames.py、native_provider_worker.py、native_provider_actor.py、native_provider_gate.py。帧长最多 24 MiB，请求正文最多 8 MiB，响应最多 16 MiB；重复 JSON 键和非有限常量拒绝。两侧分别限制次数，失败不恢复已经预留的请求槽。未授予任何付费派发资格。

这是缓冲式 HTTP/SSE 正文通道，保持字节不改写，但整段收齐后才交付，因此不保留事件到达时序或首字延迟。时间上限包含派发截止和外层进程超时，无法中断任意宿主回调或保证提供方 Token 硬上限；真实回调必须另外绑定网络超时、预算和用量回执。不能将本地循环时间作为模型/算法速度。

## 检查结果

六项针对性检查通过：帧完整性及错误拒绝、正文逐字节保持与次数上限、路由/模型/额外 URL 拒绝、失败不重试、非法响应拒绝、截止前拒绝派发。没有重跑旧上下文及任务测试。

真实同版 Linux Codex 0.165.0-alpha.1.2 通过该通道连接本地固定程序 Responses 服务：

1. 原生第一次请求中，夹具工具结果为实际 WSC 概览，逐结构比较相等。
2. 固定程序响应声明 WSCContext 调用，原生客户端实际生成动态工具回调，宿主通过真实分派器读取外置原文。
3. 原生第二次请求带回查询结果；程序解码并核对 revision=23、status=current，随后完成该轮。
4. 同一原生 command/exec 验证真实存在的 WSC 数据库、结果数据库及 /proc/1/root 变体不可读；第三次 HTTP 请求返回 429，未增加宿主派发数。

回调来自原生客户端对脚本提供方输出的处理，不是人工直接调用回调处理器，也不是实际模型主动补证。呈现回执在捕获到真实发送的请求后登记，但接收方仍是脚本服务。不能把它标记成实际模型已使用历史。

## 失败保留

v1 验证器先尝试空 WSC 快照，被 invalid_fold_boundary 拒绝，未启动进程。v2 在原生首次日志持久化前构造路径映射而失败；复用已有应用会话的启动顺序，先注入事实并短时等待原日志出现，不造空日志、不放松映射校验。v3 两请求闭环通过。v4 在此基础上增加实际私有文件读取与第三次请求拒绝检查，通过后冻结当前源码。各轮目录、错误、源码和原始传输记录保留，未删除失败。

证据：D:/agent-task-runs/wsc-native-provider-bridge-20261030-v1/v2/v3/v4。v4 保存登记、原始请求、原始响应、动态回调、私有边界检查和 WSL 清理回执。原始数据及代码是脚本生成的确定性夹具，不是任务质量标准答案泄漏给实际模型。每轮 WSL 初始停止、独占启动，清理 terminate 成功。

本机认证能力仅检查了字段存在性：默认提供方 openai、ChatGPT 认证记录存在，没有环境 API key。没有打印、复制、归档任何凭据；该信息不证明登录仍有效或提供方可用，也不表示额度不足。
