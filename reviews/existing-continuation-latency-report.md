# 既有 B/C 日志的耗时拆分

本轮只分析已存在的 2026-10-27 运行日志，没有模型调用、会话启动、测试、性能回放或新实验。分析对象为已报告的三条成功 C 链、三条历史原生 B 链，以及保留的 deferred_catalog 失败尝试；不是用户后续性能改动后的实测。没有删除失败、补跑样本或修改预算。

机器数据为 `existing-continuation-latency-v2/analysis.json` 和 `phases.csv`，包含 19 个阶段、7 条主机时间线及输入 SHA256。早一版 `existing-continuation-latency` 保留；v2仅追加均值和分析器指纹，同一批原始记录没有重复计入。

## 直接结论

这批记录里，本地精确来源恢复不是几十秒差距的主要来源。明显的两部分是服务端非工具区间，以及研究脚本的多进程启动、导入和资格检查。服务端非工具区间无法进一步可靠拆成模型推理、预填充、提供方排队、网络和运行时，因此不能把它全部归因于模型能力、温度或 WSC 外部实现。

这不代表 WSC 整体已经足够快，也不代表本地 I/O 总成本很低：生成材料、制品发布和其他未完整埋点的步骤仍有独立成本。正常任务能否跳过 C2、恢复成本会不会转移到任务回合，目前没有执行证据。

## 三、主机时间线中的研究集成成本

按同一进程的单调时钟把每条时间线划成互斥区间：优先阶段执行，其次选材流水线的阶段外部分、启动/关闭、其他已埋点 RPC，剩余为未归因。父子 span 不重复相加。

|C 链|记录区间秒|阶段执行及对账|选材流水线阶段外|启动/关闭|其他 RPC|未归因|
|---|---:|---:|---:|---:|---:|---:|
|R01|87.072 下限|56.654|0.486|14.113|6.759|9.061|
|R02|101.636|65.410|0.628|14.820|9.220|11.557|
|R03|87.423|48.675|0.549|18.384|8.443|11.372|

原生 B 对应启动/关闭为 3.028、3.847、3.899 秒。C 创建额外 bootstrap、parent、两组 selector/receiver 及 probe，这是研究脚本的实际系统开销，不能全部记作压缩器算法计算，也不能从真实实验总账中删除。

C 的其他 RPC 中，资格检查 `command/exec` 合计分别为 4.884、5.030、5.279 秒，用于既有脚本的冷文件/manifest 可达性核对；额度读取为 1.111、2.196、1.226 秒，其余主要为材料注入。部分检查是实验专用，但还未证明生产宿主可以省掉哪些工作，因此不计算“去噪后净提速”。

未归因的 9–12 秒混合了未埋点的核心/制品操作、协调器校验和日志等。它不是零成本，也不能全部叫外部噪声。选材流水线阶段外不到一秒，不代表整个 WSC 本地算法耗时不到一秒，因为 preflight 和发布不全在该 span 内。

记录区间与外层完整墙钟端点不同；R02/R03 外层仍是原来的 101.671/87.453 秒。R01 收尾异常后完整墙钟未知，87.072 继续只作下限，不拿三个区间均值冒充完整系统均值。

## 四、失败样本仍单列

deferred_catalog 阶段 outcome 为 38.094 秒、服务端 turn 为 37.415 秒，其中动态工具并集 0.044 秒，非工具区间 37.371 秒。四个可见回调本地总计 10.042 毫秒；此时服务端耗时仍占主要部分。catalog 回调确有额外工作，不能把这组 10 毫秒与成功组单次亚毫秒直接当格式优劣结论。

该尝试触及四响应上限，没有最终草稿或 QA。已知用量与未知状态不变，不赋予正确率。phase outcome 采用较粗的时钟，可能比高精度外层 stage span 长几毫秒；不跨时钟强行求负的“开销”。

## 五、对后续方向的影响

继续优化来源读取微秒级路径，难以独自收回这批记录中的几十秒差距。更有针对性的方向是减少不必要的模型选材回合及研究脚本的重复 actor/材料处理，但必须保持完整新尾部、正常恢复能力、权限和持久化语义。

不能把“减少 actor”直接认定为可兑现的 14–18 秒收益：其中部分 actor/动作仍有职责；跳过 C2 后，任务模型恢复的回合数、服务耗时和正确率均未知。不能用当前输入表示的历史结果证明用户最新源码的性能。

下一步仅基于这些既有记录，把正常续接与重新压缩的职责和成本归属整理为一个收敛方案，保留必要检查，避免新增压缩格式或重复恢复链。用户停止实验的要求继续有效；实施候选未经验证不得进入默认链路。

复现本报告的离线分析：在仓库根目录执行 `py -3.11 -B -X utf8 wsc/validation/report_existing_continuation_latency.py --out <新的输出目录>`。只读取固定的历史路径并生成派生文件，不启动 Agent 或调用模型。
