## 真实接入和可控条件

`late_recovery_case.py` 独立构造带预定义 oracle 的新案例，原早位案例生成器未改。`late_recovery_qualification.py` 复用原核心 prepare/generate/stage/export/import 及 native 进程/回执机制；第一次选材也是模型生成，非固定全选/空选代替。

两个选择器都用相同私有 minimal runtime、compact wire、BudgetResultSourceToolHandler 与 SnapshotLiteralAccess；C2 使用全新选择线程，未继承原始 prefix 对话。最终接收端仅导入真实发布的 WSC items，冷资源在正常环境可读；答题使用独立兄弟分支，未污染接收主干。真实选材完成后才写 oracle 文件。

actor 使用登记的本机固定 CLI、gpt-6-luna、effort=max。输入/输出/缓存/推理 Token 和阶段秒数均有 native 回执。模型温度/随机种子和内部实现无法完全控制；货币金额未知。预算预登记 520000 Token / 12 响应 / 900 秒；每次选择最多 200000/4/240 秒，查询最多 120000/4/120 秒。服务检查通过后才派发，无自动重试。没有调用原生 compact，也没有伪造 B 摘要/评分或 atomic install 回执。

机械准入先用空选择作接口预检，只证明导入/绑定/大小/读取通路；真实资格在新目录重建并使用两次真实模型选择。不能把零模型准入当语义选材成功。
