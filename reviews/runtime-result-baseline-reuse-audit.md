# 工具结果外置新增臂：旧基线复用审计

2026-10-30。只读取既有文件，模型调用 0，不改旧验收矩阵、不重跑旧组、不更改旧成绩。

## 决定

现有旧模型结果不能直接作为新 Linux/受控网关宿主下的新增外置臂对照；可以复用封存历史、初始文件、程序验收数据和选材草稿，先做离线绑定及表示检查。

当前 32 KiB 默认阈值下，五个封存任务历史和已完成 T1 六条续接轨迹均未出现超过阈值的单条可观测文本结果。直接付费重做这批记录没有检验超大结果外置的暴露条件，因此不追加该组实验，也不为制造命中而临时降低阈值或给旧历史灌水。

此结论只覆盖当前默认的大结果外置触发条件，不证明所有去噪策略、其他阈值或真实生产原始输出均无收益。上游 stdout 在进入原生模型可见记录前可能已经截断，当前审计不能反推出它的真实大小。

## 可复用的数据

T1 三组前缀 history_sha256 一致；第一组 inputs.json 原始文件摘要与两次后续登记匹配；任务公开摘要及后续登记的基线文件摘要均通过核对。没有发现这几项封存数据被改写。

|材料|用途|限制|
|---|---|---|
|原始历史前缀|精确复用输入事件与先后关系|不能悄悄改写历史控制或原文路径|
|初始代码、oracle、约束|复用任务与确定性评分数据|当前执行环境、验收器版本及可运行性须另外确认|

|旧模型用量、结果、失败|历史报告及问题定位|不与新条件拼成配对成本或成功率|
|原生 opaque 压缩状态|保留历史凭据|没有解密、读取摘要或声称跨宿主可恢复|

三份已有选材原成本分别为 25567、26378、26733 Token。复用可以避免再生成一次草稿；完整重建成本仍包含原生成代价。不能一方免生成而另一方重新压缩，再把差额归为算法优势。

## 不能直接比较的条件

- 旧原生 Windows 可执行文件与新 Linux 文件不是相同字节，虽然版本号相同。
- Python 由 Windows 3.11.9 变为 Linux 3.11.18；旧请求明确写 .runtime/python.exe，不能原样在新环境执行。
- 旧文件拒绝规则存在已确认的旧答案文件可读缺口。不能据此认定旧模型作弊，也不能把旧规则当作等价的新闭集挂载。
- 旧原生默认传输与新宿主缓冲网关的头、缓存及延迟没有全面等价核验。新恢复准入三次缓存输入均为 0，不能和旧组高缓存直接相减。
- 旧发布绑定 Windows workspace、native_source_refs_v1 和 codex_indexed_sections_v1；新旁路是显式映射工作区及 context_checkpoint_v1。不能同时变更表示和外置策略却只归因去噪。
- 新宿主的实际原生检查点安装还没有准入证据；真实模型字段恢复不能代替该项。

## 后续准入顺序

1. 先完成映射宿主的检查点安装/回执/恢复资格，尽量复用已有草稿，用零模型协议检查；不重开字段取值准入。
2. 为完整任务增加机制暴露检查：实际生产者正文是否可获得、类型/状态/控制豁免是否明确、是否真的超过阈值、是否需要中段信息；没有暴露不付费跑外置臂。
3. 新增外置臂与相应控制臂共用同版宿主、任务、输入、模型、工具权限、恢复资源、触发点和表示适配器，唯一计划差异为外置/去噪策略。原生二进制与压缩算法不改。
4. 旧基线只在条件确实相同且凭据齐全时复用。无法复用时保留历史结果；新控制必须另登记，不能冒充已经做过同条件对照，也不自动扩大次数或预算。
