## 结构性原因与修复规则

此前运行器把 `execution_scope` 放在生成请求的独立字段中，WSC 事件索引只有原始 54 条历史来源。模型可以读到该事实，却没有可直接引用它的来源别名。真实 reference 草稿因此给相关线索留下空 sources，准备视图时报 `clue_source_missing`；word 草稿虽然使用非空历史来源，但这些事件也不能完整支持生成目录及未注册续接等新事实。

修复复用已有 `Event(kind="observation")`、来源授权、内容绑定、冷档导出与引用编译；没有新建表、平行事实存储或语义真值判定器。独立生产者模块 `experiments/native_scope_observation.py` 从已绑定原生日志和当前登记生成一条观察，两个生成入口在 capture 前登记它。请求的 execution_scope 现在只指向 `s55`，其值在普通材料/目录中可见和可选。

同一观察重放使用相同身份，不重复插入；观察时间或登记发生变化时产生新的历史记录。原 54 条来源逐值保持不变。该身份是 WSC 来源身份，不是新增的原生执行或宿主安装回执。

## 三项复审

职责：运行器只陈述登记、观察和身份。生成目录明确标为登记目录，不冒充已观察到的执行目录；历史执行目录来自实际 turn_context；续接未登记仍是未登记。观察记录不冒充用户或 developer 消息，不写行动指令。模型仍决定保留、理解和引用什么。

信息边界：原始上下文记录的完整 JSON 值放入冷 payload，原日志字节身份、物理行号、上下文 JSON 值的规范化哈希及原观察时间一起保留。公开 text 只含必要事实投影，登记观察时间与历史 native_observed_at 分开。原日志字节排版不冒称由规范化 JSON 保留。来源仍经过既有授权和快照检查，引用与事实不一致在执行层拒绝。

成本与复杂度：实际冷 payload 3970 字节，公开投影 1138 字节。数字只是 UTF-8 字节，不是模型 tokens 或收益。核心存储、发布状态机、默认切片策略未改；新逻辑集中在生产者模块，两个实验入口共用。当前只是补上可引用性，不证明模型会自动正确引用，不以新增字段或测试数量当收益。
