## 实现与安全边界

新增独立 `native_event_table.py`：将 `text_in_frontier is False` 的旧事件共同字段置于明确 defaults，变化字段放入具名 row_fields，每行保留原 event_index；新事件保持完整字典。缺失/异构旧行形状、保留列名冲突、没有实际字节收益时原样通过。没有丢弃事件、改正文、选择重要内容或给来源排名。

共同字段比较采用严格 JSON 表示，false、0、null 不合并；缺失字段不补为 null。解码校验绑定哈希、行宽、列名、索引类型/范围/唯一性和完整覆盖，布尔索引不能当 0。位置字段保留原事件顺序，角色/来源身份/引用/预算和自由文本原样可还原。

`native_incremental_generation.generate(..., cold_event_table=True)` 显式启用，在输出 schema 生成后只改变输入材料表示；输出 schema 和草稿规范化/核心编译不变。原默认 False。实验入口 `--cold-event-table` 与策略 `/event_rows_v1` 登记，绑定文件仅主机保存，不额外塞给模型。

实际新请求解码后，除实验专属冷清单 path/sha 两项主机定位字段外，和原请求严格相同；输出 schema 完全相同。两份冷清单的 643 个来源身份/时间/内容 hash 相同，审计逐个核对对象文件内容一致。因此没有为了省输入放松引用或偷偷裁掉事实。
