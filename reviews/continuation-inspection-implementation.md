# 旧选择机械续接检查：独立候选实现

本轮承接“查清第二次选材何时真的必要”。实现只覆盖只读机械检查，没有接入默认执行路径，没有调用模型、运行测试、性能测量或方案实验。语法解析和交付文件哈希只用于文件完整性，不证明运行正确性或收益。

## 交付与边界

新增 `wsc/src/wsc/continuation_inspection.py`，入口 `inspect(core, snapshot, previous_view_id, *, max_view_bytes, semantic_reselection_requested=False)`。返回 `wsc.continuation_inspection/1` 事实对象，`executable` 恒为 false；不返回可安装视图，不生成 Selection，不生成模型提示词，不调用发布接口。没有在包入口或现有调用方中启用它。

引擎可以检查身份、源/视图摘要、精确记录版本、片段范围、权限、工具配对与已知预算；不能决定哪些语义可以删除，也不能把旧理解升级成最新理解。调用方是否明确请求语义重选仅作为事实回传。

## 已写入的机械检查

- 使用只读 SQLite 事务和 `query_only=ON`；调用非索引 snapshot 校验，避免懒建 presentation 索引。复用 Store 的连接关闭机制，结束时回滚只读事务。
- 通过统一 `view_record` 核对旧 body digest；核对旧 session/workspace、源前缀摘要及历史工具配对、呈现回执。
- 核对已选来源原值、旧必留消息、理解精确 ref/内容、clue 来源边界和 excerpt 的原文范围/hash；对相关来源和完整新尾部执行现有访问检查。
- 原样列出旧选择身份和全尾部 ID/digest，不按语义过滤；报告旧视图状态、是否当前 head、cursor、未决操作和不同 epoch。
- 理解 epoch 有变化时明确标记变化清单不完整，不自动选择新 revision。外部文件引用只验证历史片段，不读取当前文件，列为待重新观察。
- 提供诊断用“旧选择＋全尾部”内部存储形态字节数及超预算事实；这不是有序可发布视图，不包含新鲜 live-reference 结果，也不是宿主 Token 数。

## 尚未完成，不能据此省掉 C2

1. 重建新检查点的有序渲染尚未实现。当前普通渲染可能把旧 clue 放到新增消息之后，因此模块不返回拼接后的 body，也不发布。正常继续已有接收线程时，完整新尾部已可直接追加，无需重建渲染；详见 continuation-host-interface-review.md。
2. rendered bytes、宿主实际 Context/输出预留、opaque 可呈现性、正常任务的证据恢复交付均未验证。字段明确保持 unknown/false。
3. 理解变化的完整增量来源尚缺；全局 epoch 变化不能直接认定相关，也不能据此忽略。
4. 检查结果仅绑定读取时刻。ACL 回调的行为由调用方实现，SQLite 事务不使外部权限或文件成为原子快照；后续发布必须重新执行原有校验。
5. 此候选沿用全前缀及 presentation 扫描；没有声称长期复杂度或性能改善。
6. 上一轮发现的原 `frontier` 旧 body digest 校验缺口仍在原路径中，本次仅让新候选走统一校验，不宣称已修复主链路。
