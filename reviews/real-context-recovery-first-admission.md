## 登记与结果

先用固定第一方 Codex models 路由 GET 检查认证及通信，HTTP 200，目录 10 项，包含 gpt-6.1-sol。GET 不生成回答，目录存在不代表推理权限。

依据 [OpenAI 官方网关说明](https://learn.chatgpt.com/docs/enterprise/connect-to-a-gateway)，宿主读取现有 ChatGPT 认证，固定第一方 Codex 后端；凭据只在宿主请求头内，不进入隔离环境或归档，不跟随重定向、不重试、不切换提供方。

真实准入单独预注册 gpt-6.1-sol/max、100000 Token / 4 响应 / 180 秒、并行 1；温度和 seed 未知。原研究根分配从 11071795/60/2295 扣除该次预留，算术剩余 10971795/56/2115。这里是分配，不是实际消耗或未知用量的确定上限。

任务原文是含 7000 个记录的确定性夹具，其中第 3500 项替换为随机 nonce。模型只收到有界概览，登记前断言 nonce 不在概览中；用户问题要求返回该项及 result:rN 引用。评分器程序比较精确值、引用、实际回查和用量完整性；不使用额外 LLM。此项只验外置结果恢复，不包含压缩或 B/C 收益比较。

结果：第一笔 POST 获 HTTP 200、102429 字节正文，媒体类型解析为 text/plain。接入器仅允许 JSON/SSE 媒体类型，于是拒绝响应；正文未保存，原生客户端没有收到模型输出，未触发 WSCContext 回调。不能确认该正文是合法 SSE，也不能从 HTTP 200 证明模型正常完成。

**这是接入失败，不是模型答错或 WSC 信息恢复失败。** 缺失原始响应无法补造；真实生成内容、输入/输出 Token、缓存 Token 均未知。已知响应回执为 0 不代表实际成本为 0。该次 100000/4/180 分配冻结，不回收、不覆盖旧未知。没有自动重跑。

## 结构性根因与规则

1. 原始 HTTP 数据与协议准入耦合：仅在媒体类型通过后才进入原始响应归档，导致不支持的类型连审计证据也丢失。规则改为先有界持久化收到的原始字节，再判断协议；流中断保存部分内容并标记不完整。
2. 仅按 MIME 判断响应：不能直接放行所有 text/plain，也不能认定原失败正文必然合法。新旁路只对能解析出 Responses 创建事件及合法终止事件的 SSE 正文调整媒体类型，正文保持逐字节不变，记录原始及有效类型；其他类型拒绝但保留原文。
3. 宿主异常没有对应的传输完成路径：异常逃出循环导致客户端只能等待超时。新增 dispatch 包装，宿主异常立即返回中性 JSON 502，不恢复请求槽，不重试。

仍保留缓冲式传输限制；这些修复未改变 WSC 选材或原生压缩算法。真实回调必须继续绑定网络超时、根预算及完整回执，不能用媒体类型修复声称模型质量已通过。
