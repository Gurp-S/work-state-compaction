# 大历史后部证据：零模型可达性检查与可选旁路

2026-10-27。本轮 0 模型调用。先复现，再做独立可选实现、前后比较和原始输出审计；不重跑上一组 B/C，不改原生 B，不把源查找测试写成压缩质量评分。

## 已复现的问题

旧 SnapshotSourceAccess.find 对每个不匹配来源也重新读数据库、校验整条记录，累计使用 512 条 live-row 校验预算。已知别名可直接 read，但模型不知道别名、从默认 cursor=0 按字面查找时，位于第 512 条以后的目标会不可达。错误明确返回 partial，不是文件丢失，也不是偷偷误报不存在。

四种历史规模，各将唯一目标放在第 6 条及倒数第 8 条，共八个确定性案例。全部原文确实存在且已知别名读取正确；查找字符串由测试调用方直接给定，没有使用模型。

| 历史条数 | 后部目标序号 | 旧 find | 新快照正文查找 |
| ---: | ---: | --- | --- |
| 128 | 120 | 找到，1 调用/128 校验 | 找到，1 调用/1 校验 |
| 512 | 504 | 找到，2 调用/512 校验 | 找到，1 调用/1 校验 |
| 1024 | 1016 | 3 调用后预算耗尽，未找到 | 找到，1 调用/1 校验 |
| 4096 | 4088 | 3 调用后预算耗尽，未找到 | 找到，1 调用/1 校验 |

含早期目标总计旧 6/8、新 8/8。这里是**明确字面目标的来源可达性**，不是模型问答正确率，更不是 WSC 已在八个压缩任务中取胜。上一组 build-003 位于很早的来源，无法覆盖本问题，不能从那组 C6/6 推广到大历史。

## 结构性修订和语义边界

根因是将“发现候选”与“对候选当前存储作证据校验”放在同一个全量逐行流程，发现不相关日志也耗尽有限的证据读取预算。

新独立 `wsc/src/wsc/snapshot_literal_access.py` 提供 SnapshotLiteralAccess。构建时把**已捕获、已封存快照的公开文本**绑定到原来源别名/摘要，保留不可变字符串引用。模型提供 literal，搜索按原始来源顺序精确匹配，返回每来源第一个匹配；不作关键词相关性排名、语义抽取、重要性决策或新旧状态覆盖。

候选命中后仍从数据库读当前行，校验当前权限、记录完整性与同快照封印；返回片段来自通过校验的当前行，不用缓存文本补救坏记录。来源丢失/篡改/权限撤销只返回事实错误，不能把旧缓存升格为当前有效事实。

**负结果的契约不同，不能隐去：** complete 只表示该封存快照的正文查找覆盖完成，不证明当前数据库中每条未命中记录仍可用或完整。模型可见结果含 `search_basis=sealed_snapshot_public_text`、`storage_validation=returned_matches_only`，描述也明确负结果不是存储健康证明。旧路径对未命中的坏行也会报错；新路径不做这种全库健康扫描。因此不是完全等价替换，也不是严格相同资源条件的算法实验。

匹配来源的权限前后校验保留；不授权的文本不计为已检查正文，也不因其长度返回正文预算错误。目录总正文长度只留在主机对象，不进工具结果。新的测试覆盖了权限撤销、不匹配坏行、匹配坏行、数据库 data+digest 同时被替换、快照对象随后被修改等情况。

## 资源上限与实际代价

原读取/输出硬边界不增：最多 8 调用、累计 512 条 live 校验、每次最多 8 匹配、单返回 16384 字节、累计检查正文 2MiB。原 `max_rows_per_call=256` 在新路径明确指 live 校验；快照扫描单列预算，不能把新扫描量说成原来 256 行内完成。

新增目录边界：最多 65536 个输入事件、引用公开正文总量 16MiB；每次最多扫描 8192 个快照来源、协作式 250ms 扫描期限。期限在来源间检查，不能抢占正在执行的权限回调/数据库操作，**不是硬进程墙钟保证**。超量/超时返回 partial 与未扫描 cursor，不把未覆盖当不存在。目录不写新增持久化全文副本，但依然消耗构建时间和 Python 容器内存。

最终源码后本机一次带 tracemalloc 的 4096 条/后部目标前后测量：

| 指标 | 旧路径 | 新旁路 |
| --- | ---: | ---: |
| 构建秒数 | 0.142 | 0.311 |
| 查找秒数 | 0.057，未找到 | 0.070，找到 |
| 构建+查找 Python 峰值 | 1.156 MB | 1.606 MB |
| live 校验条数 | 512 | 1 |
| 逻辑正文检查字节 | 15252 | 125886 |

这不是总体更快/更省内存：新路径完成了更多扫描工作，并付出约 0.18 秒额外构建+搜索时间及约 0.45MB 额外 Python 峰值，换来后部目标可达。相同预先捕获的快照约 0.040 秒单列，既有快照/进程总峰值未计入上表；物理 I/O 未知。测量含 instrumentation，不作统计性能结论。目录和快照仍是 O(N)，没有关闭历史 001/011，也没有为 payload 或整个进程提供 16MiB 保证。

预期可能减少模型分页/无效恢复轮数，但**本轮没有模型实验，不能宣称 Token、回答正确率或整体成本已经改善**。若模型不知道正确 literal、选错来源或查询内容超出这些预算，仍可能失败。不会通过扩张调用次数或删除失败换漂亮结果。
