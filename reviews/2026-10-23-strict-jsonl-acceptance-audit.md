# 严格 JSONL 登记验收覆盖审查

这是对已结束实验的审查，不修改原验收器或补记原模型成功。完整需求在`experiments/strict_jsonl_study.py::STAGES`，原11个具名方法在`strict_jsonl_grader.py`。数字是方法数，不能理解为穷尽了全部输入组合。

| 原需求 | 登记证据 | 覆盖边界与缺口 |
| --- | --- | --- |
| 各对象深度重复键、解码等价键、同值重复 | duplicate_keys方法 | 已含嵌套数组、Unicode转义、带/不带末尾LF |
| 字符串不递归解析 | strings方法 | 已含同形NaN/Infinity/重复键字符串 |
| Unicode、物理LF行号、原始哈希长度 | unicode方法 | 已测U+2028、空白行、中文；不是任意Unicode空间的穷尽证明 |
| 真正部分尾行、坏UTF-8尾行、缺文件 | partial_tail方法 | 已测未完成JSON和单字节无效UTF-8；未穷尽所有尾行组合 |
| 中间坏行、记录形状 | invalid_interior方法 | 已测非法UTF-8、非JSON、数组与非字符串type |
| 非有限常量及浮点溢出 | nonfinite方法 | 已测正负常量、正负溢出；错误优先级原需求未约定 |
| 无LF的完整非有限记录不能当尾行丢弃 | complete_unterminated方法 | 登记只测NaN，不能以此代表所有非有限表示 |
| 有限浮点和合法大整数保值保型 | finite_numbers方法 | 原仅120位正整数；没有跨运行时4300位阈值、负大整数和局部/全局转换限额边界。补审5000位反例：C失败、B通过 |
| 单行原字节预算、LF不计CR计入 | line_budget方法 | 已测中文多字节、CR、恰好允许和超限、空白段 |
| 预算先于解码/解析 | oversized_invalid方法 | 已测坏UTF-8超限优先；未单独覆盖所有JSON错误与预算组合 |
| None无限额、正整数排除bool | default_unlimited方法 | 已测None、True/False、0、负数、浮点、字符串 |
| 回执只适用于指定阶段/版本 | 实际交接与清单核对 | 两臂区分旧/新阶段；原哈希计算域含混，另有旁路修复 |

当前已证实的合同失败是大整数，不把其余“未覆盖”直接判成实现错误。数值要求来自第一次边界之后当前的新请求；不能从C失败反推该要求被压缩遗漏。

验收可见性也存在设计缺口：每阶段只运行部分方法，但验收副本包含整份测试文件，B在第一次扩展实际读到了下一阶段方法。未来必须在登记前明确测试公开与否；若研究的是新要求到达后的续接，未来阶段测试不能提前随验收副本落盘。仅把目录命名为private不能形成隔离，不能通过改变原生B权限或提示制造优势。

下一个付费研究的准备顺序：先按书面需求登记值域、运行时阈值及交互边界；用已知旧实现和独立反例校准验收；核对每阶段可见材料；再检查C真实产物是否满足书面合同后考虑B。当前没有新任务登记或付费启动。这些步骤不能自动证明语义完整性，人工审查仍需独立于具名检查数。
