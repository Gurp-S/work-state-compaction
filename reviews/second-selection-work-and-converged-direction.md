# C2 实际工作清单与收敛方向

本次只读既有三条成功 C 链的数据库、生成请求、选材结果和工具回执。数据库以 mode=ro/query_only 读取，前后主文件 SHA256 不变；没有运行压缩、任务续接、测试、模型或新实验。此前失败版本继续保留，不并入这三条成功链冒充通过。

机器数据：`existing-second-selection-inventory/inventory.json`。新工具仅离线列举来源身份、精确字符范围及内容一致性，不作自然语言评分或语义判断。

## 1. C2 到底做了什么

三条链的完整来源序号、cut 和选中来源集合相同，但内容 ID 绑定各自会话，不能跨会话直接拿别名当同一对象。

|工作项|三条链共同观察|
|---|---|
|C1 边界|641 条来源|
|C1 选中整个来源|s1 跟踪规则、s640 build-320 回执、s641 关联日志|
|新增原文|s642 build-321 回执、s643 当前审计请求|
|C2 选中整个来源|s1、s540 build-270 回执、s642、s643|
|新选中的历史来源|只有 s540，原文 227 B|
|从工作视图删除的旧来源|s640、s641；原始历史并未删除|
|理解记录|R01/R02 无既有 M；R03 的一个 @1 记录被 C2 取消选择，没有自动生成 @2|
|clue|三个 C1 clue 均没有按文本及来源完全相同地保留；不据此判断新 clue 好坏|

C2 同时做了三种不同工作：恢复一个此前未选的历史回执、依据新原文重选工作集、重新表达 clue。不能把它描述成“仅缩减了几十字节”，也不能认为删掉 C2 后这些职责都自然完成。

不过，恢复某条历史原文并不在机制上要求再生成整个工作视图。正常任务模型可以通过已授予的读/查找工具自行补证；这是待接入并待验证的方向，而不是已执行结果。

## 2. 哪些恢复输出与已有输入精确重叠

逐条核对实际 C2 request 的新增 spans、previous_excerpts 与工具回执中的同一 source ID、offset/end、原文值：

|链|实际 read 顺序|此前未在输入中出现的返回区间|此前已完整内联的返回区间|
|---|---|---|---|
|R01|s540|s540|无|
|R02|s540、s1、s642|s540|s1、s642|
|R03|s540、s642、s643|s540|s642、s643|

合计 7 次读取中，3 次带来此前未内联的来源原文，另 4 次返回已内联的同一原文范围。4 次重叠原文合计 862 B，回执编码合计 3776 B（含身份、范围、hash、metrics）；三次 s540 原文合计 681 B，回执合计 2898 B。

这不是关键词评分：判断依据是结构化身份和范围的完全一致。它仅证明原文重复交付，不证明模型已经注意、理解、信任或正确使用了那些文本，也不证明查询前后的权限/存储观察可以互换。引擎不能因为文本已出现就拒绝合法的重新读取，不能借此自动判断“证据已充分”。

C2 request 的事件 text 字段已转成 spans，不能只检查 text 是否为 null 就断言新内容不在输入。此次核对确认为 s642/s643 的 spans 拼接与密封来源全文完全一致；s1 则通过 previous_excerpts 的来源范围核对。

## 3. 不能兑现为收益的部分

三次 C2 的实际消耗仍是 64061、96285、65061 Token（均值 75135.7）；阶段为 24.547、27.922、27.906 秒。未运行没有 C2 的任务，所以 `skip_C2_correctness/tokens/seconds` 均保持 null。

227 B 的唯一新历史来源，不意味着用 227 B 就一定能完成任务。任务模型仍需发现信息缺口、定位来源、读原文并正确使用。工具注册/描述、原有上下文、后续响应和错误恢复也有成本。不能把整段 C2 Token 或时间直接计为可节省值，也不能从回执重复字节反推 Token 节省量。

R03 的旧理解显式说明其观察只适用于当时快照。沿用它时必须保留这种历史适用范围；不能把“未变的旧理解”和“当前仍成立的理解”混为一谈。三条链的 C2 取消旧选择，是模型既有决定；未来机械延续不应悄悄仿照这些决定删除 s640/s641 或旧 M。

## 4. 收敛为一条职责清晰的路径

不新增压缩格式、独立恢复模型或第二套冷层。保留以下分工：

1. **正常任务持续执行**：任务接收器沿用已有效导入的旧帧，按原序携带完整新增原文；不因检查点编号或有新消息就固定再创建 selector/receiver，也不为了普通续接再走 prepare/stage。需要正式新检查点时仍走原有发布与确认协议。
2. **恢复属于正常任务能力**：在接收器创建时授予既有精确来源工具，由任务模型决定是否调用。复用原来源存储、权限和 hash 校验；按前一份端口契约固定 owner、来源范围、累计限额及关闭行为。普通任务不套用选材器的精简运行配置。
3. **语义缩减仍归模型**：明确请求重选，或完整材料超过真实可用容量并需要舍弃/改写时，再进入现有显式选材 API。引擎只提供容量/绑定事实，不能按关键词删减、替换理解版本或自行决定重要性。
4. **机械失败先保持边界**：身份、权限、旧 view digest、工具配对、发布恢复不成立时，返回现有事实状态或拒绝执行；不把坏绑定交给模型修补。旧选择身份、来源范围和当前观察不能互相冒充。
5. **成本只记一次且记完整**：任务恢复、模型回合、必要发布/权限检查和所有失败都在 C 系统账上。记录研究专用启动/资格成本，同时保留真实总耗时；不能把必要步骤移到计时外。

这是一条候选运行路径，不是已经默认启用的优化。当前宿主真实 Context Token/输出预留接口仍缺，不能用内部 body 字节预算冒充容量准入。已有长目录压缩、端口检查等候选均不得因本报告被提升为已验证收益。

## 5. 当前落点

本轮没有继续堆叠未验证执行模块。既有静态检查模块未启用，原生 B 不变。三成功链仍只证明原两次选材协议下的历史 6/6；新的单任务续接方向没有正确率或收益数据。

下一步限静态代码审查：确认上述路径是否有可用的真实容量入口及来源工具生命周期实现；没有就列为未交付，不再通过增加包装器制造完成感。用户禁止实验期间不补跑验证，也不宣称超过原生 Codex。

离线复现：`py -3.11 -B -X utf8 wsc/validation/inventory_existing_second_selection.py --out <新的输出目录>`。只读取固定历史产物并写出工作清单，不启动 Agent。
