# WSC 配套去噪工具：XEYO 现状与可加的东西

2026-10-27。目标：给 WSC 加一组"上下文管理去噪工具"，放在单独文件夹里。先盘清 XEYO 已经有什么，避免重复造。

## 一、XEYO 已有的去噪能力

| 模块 | 做什么 | 关键约束 |
| --- | --- | --- |
| `tools/spill.py`（T1） | 超预算工具输出先落盘到 `~/.xeyo/spill/`，只在模型可见投影里截断 | `O_EXCL` 独占、0600、7 天保留清理；落盘失败绝不抛错，宁可超预算也不给假证据 |
| `engine/repeat_fold.py`（R2'） | 同签名 + 字节级同输出的空转折叠，连续第 3 次起换成一行说明 | 只跟"上一次同签名输出"比，输出一变即重置；保持 tool_use ↔ tool_result 配对 |
| `engine/aging.py`（T27） | 投影层老化存根，近档富信息、远档极短，默认**关闭** | 错误结果与结构化结果豁免；措辞中立，不劝模型重跑 |
| `engine/semantic_fold.py` | 步骤语义索引，零模型调用 | 只生成标题，不改内容 |
| `engine/compact.py` | L5 摘要记忆投影 | 不改 MessageStore / JSONL |
| `engine/manual_compaction.py` | 手动压缩，走和 query loop 同一套声明事务 | |
| `memory/offload.py`（L3） | 超长工具结果外部化到文件 + 固定预览引用 | |
| `memory/summarize.py` | 按内容类型抽短摘要（C2 语义片段） | |
| `memory/wsc_size_prune.py` | 工具结果尺寸侧修剪 | 旁路候选，**未接主链** |
| `memory/wsc_object_gc.py` | 基于 root 清单的显式回收 | 清单不完整就绝不删 |
| `memory/instruction_maintain.py` | XEYO.md 维护：模板 / doctor / 过期探测 / 嵌套懒加载 | |

一句话概括：XEYO 的强项是**运行时**——流式截断、落盘、空转折叠、老化存根都在 live 链路上。WSC 的强项是**封存材料的来源与可回查**，两者不重叠。

## 二、WSC 侧真正缺的

WSC 现在只做"选材 + 预算 + 发布"，对**选进来的内容本身**不做任何确定性清洗。缺的是"把一批已封存来源整理成更小的视图，同时保留回查路径"这一层。

不能照搬 XEYO 的原因：XEYO 的 spill / aging / repeat_fold 都依赖运行时上下文（当前回合、上一次输出、store 写入点），而 WSC 面对的是**一段固定的来源前缀**，没有"上一次"这个概念。

## 三、建议加的九个工具

放在 `src/wsc/denoise/`，一个工具一个模块，`registry.py` 统一注册。共同约束：**只改视图，不动来源**；每条动作都产出可回查指针；默认全部关闭。

### 可逆（只换表示，原文指针可还原）

| 工具 | 做什么 | 为什么值得 |
| --- | --- | --- |
| `outline_json` | 大 JSON 换成骨架：键路径 + 类型 + 长度，原文留指针 | 工具返回的大对象通常只有几个字段有用 |
| `truncate_head_tail` | 超长文本保留头尾 + 中间内容哈希 | 日志类输出中段几乎全是重复行 |
| `collapse_stack` | 重复堆栈折叠成一条 + 出现次数 | 同一异常刷屏是最常见的噪声 |
| `diff_digest` | 多个 patch 合成"文件 → 增删行数 + hunk 头" | 代码改动只需看形状，细节可回查 |

### 半可逆（丢内容，但能顺着指针找回）

| 工具 | 做什么 | 为什么值得 |
| --- | --- | --- |
| `dedupe_identical` | 同内容来源只留一份，其余记指针 | 快照里同一份输出常被重复引用 |
| `dedupe_reads` | 同一路径多次读取只留最新 + 版本链 | 直接对应 V1/V2 那个问题：旧读取留着只会误导 |
| `strip_noise_lines` | 按固定规则表过滤行（pytest 点、进度条、ANSI 控制符） | 规则可枚举、可测试，不涉及判断 |

### 元工具

| 工具 | 做什么 |
| --- | --- |
| `report` | 一次去噪的事实报告：按规则分类去掉了多少字节、可回查比例、哪些来源被完全省略 |
| `registry` | 规则注册表：id、作用域、是否改变语义、是否可回查，宿主按需开关 |

## 四、接入位置

```
来源快照 → [denoise 规则链] → Selection → prepare → 预算检查 → 视图
```

去噪发生在 `capture()` 之后、`prepare()` 之前，输入是快照的来源列表，输出是"精简后的来源列表 + 每个动作的指针"。这样 `prepare` 的必留规则、预算计算、发布协议全都不用改。

## 五、刻意不做的

- **不调模型**：所有规则都是确定性的，模型判断留给选材层
- **不改来源**：`denoise` 只产出视图候选，事件表一个字节都不动
- **不做语义压缩**：那属于选材，不属于去噪
- **不做运行时流式处理**：那是 XEYO 的活，WSC 只处理已封存材料

## 六、待定

- `strip_noise_lines` 的规则表要不要允许宿主扩展（可能引入误杀）
- `dedupe_reads` 保留"最新一次"还是"第一次 + 最新一次"：只留最新会丢掉"当时看到的内容"这一事实
- 九个工具是否全都要，还是先做 `dedupe_reads` / `outline_json` / `report` 三个最贴 WSC 目标的
