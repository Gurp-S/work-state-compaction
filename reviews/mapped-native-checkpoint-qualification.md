# 映射宿主检查点安装与回执恢复

2026-10-30。复用原 T1 第一份真实模型选材草稿，新增模型调用 0。此项不重做字段取值准入，不是 B/C 收益实验。

## 实际证明

同版 Linux Codex 0.165.0-alpha.1.2 在闭集挂载下接收 WSC 检查点后，原生日志出现与提交内容一致的记录。故障钩子在日志核对通过、宿主回执保存前抛出 TimeoutError；WSC 游标仍为 0。

随后追加原生尾部消息，正常关闭原生服务并重新启动，通过 thread/resume 恢复同一聊天；同时重开 WSC 数据库及宿主日志对象。宿主读取已登记安装意图及原生日志，重建回执，WSC 对账后 generation=1、cursor=46。检查点内容一共只注入 1 次，没有因丢回执再次提交；后加尾部消息仍在。

撤销来源权限不妨碍确认已经发生的历史安装；新的来源查询被拒绝。恢复权限后 source:s45 原文与旧来源文本精确相同。此过程用直接程序查询验证来源端口，不是模型在重启后自主调用工具。

这是实际原生服务的安装、重开与恢复协议证据。没有触发 Codex 原生压缩、没有发起 turn/start、没有模型任务续接结果。原生进程为正常关闭后重启；不当作 SIGKILL、系统断电或磁盘损坏测试。

## 新增宿主旁路

experiments/native_mapped_checkpoint_host.py 的 MappedCheckpointHost 使用现有 HostPort，不修改 WSC 核心状态机。

- 安装前绑定来源会话、宿主/客体工作区、接收线程与日志路径，重新检查候选、证据及恢复前缀；要求调用方提供并匹配新接收方 bootstrap。
- 在既有 WSC 写事务和上下文锁内检查候选，调用原生追加接口，不改写或清空原生日志。
- 注入前用既有 write_once 保存安装意图，包括原日志前缀长度/摘要、bootstrap、提交内容及预期回执。
- 有意图但结果不明时不重发。lookup 仅在原日志前缀及提交内容精确匹配后生成回执；没找到不能解释为“未执行”。
- 提交内容之后的原生尾部允许保留，不为重建回执而重放工具或删除尾部。已保存的历史回执可在原接收进程关闭后读取。

宿主仍须序列化同一接收线程的写入及访问策略变更；该模块不是跨进程/跨存储的通用原子事务。已有 write_once 的文件同步不能据此推导掉电后的目录项保证。日志校验限额 32 MiB，超过或不完整返回事实错误，不悄悄裁切。

## 草稿复用边界

从只读旧数据库取出原 46 条事件，逐条核对原 digest，保留原身份、payload、角色、顺序和文本；新快照 source_digest 与旧发布绑定相等。只按这些精确来源解析旧 sN 别名，不做关键词选材或修补错误引用。

旧草稿中的选材、理解文本、类别、scope 和线索保持，理解在新会话中重新登记为历史模型判断，不继承旧宿主回执，也不声称旧判断因此变成当前事实。新会话与新工作区生成自己的候选和发布绑定。旧数据库运行前后 SHA-256 相同。

复用了原先花费 25567 Token 的选择结果，本轮没有再生成一次。该历史成本仍存在，不能把新调用为 0 写成完整方案生成成本为 0。

## 针对性检查

6 项检查通过：安装/重放幂等性与关闭后历史回执、丢回执后重建且保留尾部、提交前未知不重发、日志前缀变化拒绝、非新鲜接收方拒绝、回执绑定/摘要损坏拒绝。测试早期有一项遗漏故障钩子而误报未抛异常，补齐夹具后通过，宿主实现未因此改变。

实际原生验证结果全部保存：旧草稿与来源一致、原生日志中安装可观察、无回执恢复、原生进程重启、同一聊天恢复、检查点只注入一次、后续尾部保留、权限撤销有效、旧原文精确可读。

本机相同版本 Windows CLI 导出的 ThreadResumeParams 显示不接受 dynamicTools；实际 Linux thread/resume 已成功。恢复后的模型请求是否包含持久化工具定义尚未验证，不能根据工具处理器对象存在就宣布模型可调用它。
