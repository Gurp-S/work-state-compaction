# 五任务 B/C 原生执行接线与首轮记录

2026-10-25。研究范围固定为五任务各三组成对重复，共十五组、三十条轨迹；当前仅运行 A3/r1 与 collaboration/r1 两组。其余十三组未执行。由当前代理直接推进，不使用子代理。

## 本次修复与证据

1. 原生多层 fork 的结束序号包含继承行数，不能拿子文件的物理行数直接作身份检查。新增 native_recursive_fork，通过外部登记父文件递归封存精确前缀，分开记录逻辑位置、继承状态与本地回执，不伪造扁平历史。真实三层记录重放及篡改、断链、改写本地前缀共四项检查通过。原单层读取器对同份输入仍报 nested_parent_unresolved。
2. 首次实际选择生成失败保留在 wsc-live-boundary-qualification-20261025-v1。材料同时公开短别名与完整源标识，输出字段允许任意字符串，而编译器仅接受别名；模型选用了公开的完整标识，触发 quote_source_missing。修复将精确完整标识和无歧义别名映射到同一源，模式也枚举这两种公开值；未知标识和歧义仍失败。对同一份原始草稿重放，旧版失败、新版通过，选择、线索、引用范围均未改写，没有重新生成草稿。
3. 增量候选 v2 将上一视图中的记录修订、选中源、线索、保留片段一起绑定。下一次选择可见这些旧选择，但不自动将整段旧 assistant 文本带回热状态。原观察时间、版本、来源哈希仍是历史事实。材料 2 MiB、准备正文 128 KiB、渲染 48 KiB 上限保持不变；失败不补写选择、不兜底重试。
4. 第一批完整 worker 的 v2 启动在付费调用前被拦截。结构性根因有两项：原生 additional_tools 条目的随机传输编号未剥离；不同进程实际获得的工具说明不同，一侧多出 request_plugin_install。不能把后者当无关噪声删掉。规则是只忽略 message/additional_tools 外层传输编号，仍逐字比较工具名称、说明、参数；双方显式固定 recommended_plugins=false、tool_suggest=false，沿用相同的其他原生设置。原始差异重放依然拒绝；修复后的四个并行零推理启动具有完全相同工具上下文。首次零推理探针未先物化历史文件，断言失败，单独保留在 host-controls-v1；v2 用事实注入后封存，四个进程均确认清理。

事故修复均在 wsc/experiments 旁路完成，没有修改项目引擎主链路。回归针对结构条件：历史身份链、公开引用命名空间、外层传输身份与模型可见工具定义的区分，而非为具体模型回答补特殊分支。

## 实际执行范围

八阶段 worker 已接入私有输入物化、双臂初始与后续 host 检查、响应边界预算、每阶段独立回执、S2/S4/S6/S8 外部验收、B 原生压缩与 C 只读选择/导出/实际 fork 导入。两臂在边界关闭旧进程树后再续接。C 对执行链事实保留 source seal；没有伪造 HostReceipt，也不把原生导入当成完整 HostPort 事务提交。

A3 每臂使用独立物理依赖文件。v2 的四条轨迹均未进入任务推理；v3 复用这些私有输入目录，前提是原准备/结果回执哈希匹配、没有执行阶段、进程全部关闭、当前源文件与冻结清单相同。A3 再逐文件核对依赖哈希、文件集合与私有文件身份，避免重复复制约 1.3 GB。v2 输出保留，v3 输出使用新目录。

原生自动注入的宿主技能通过生产者元数据单独封存并成对核对，不再次灌入 C 的业务源。用户同样文本和没有该生产者声明的 developer 文本仍是业务信息，未按字符串标签删除。

最终质量必须同时具备自动验收与当前源码绑定的界面、视觉、键盘等人工证据。仅自动检查通过的交付保留待评审，不当完整应用成功。新增适配器在作者校准后端上六项自动通过、整体仍 unknown；这只是适配器验证，不是模型交付或 WSC 收益。

## 结论边界

原先单次输出增加 9.44%、阶段耗时增加 10.08% 不能独立区分模型采样波动、压缩所改变的上下文与 WSC 开销。当前固定同一模型和 effort；没有证明接口可固定温度或随机种子，三组成对重复也不保证统计显著。不得筛选出成功样本后宣称 C 获益，更不能为了出现强烈差异调验收。

真实小边界通过不等于完整应用或三次实际压缩都通过。宿主配置比较不是 provider wire 请求等价证明；私有写目录与输入排除不是外部作者文件的操作系统读取拒绝证明。A3 验收使用合成 HTTP，不是实际账本/Tauri 端到端证明。端口已登记，但没有宣称原生开发命令受到操作系统端口强制隔离。
