# 原生状态的工作区边界

结构性根因：原生状态旁路验证了压缩输入、opaque 值和原生导入，却没有把“在哪个工作区生成”作为使用准入条件。跨工作区恢复仅增加文字映射。真实正式组 C 的五条命令都访问旧工作区，RunChecks 访问新工作区，最后把两者误判为检查来源冲突。完整失败证据在 `../experiments/NATIVE-CARRIER-PAIR-20261023.md`，不覆盖一次成功的 C 资格。

规则：当前没有建立 opaque 状态的跨工作区迁移能力；这个可选适配器仅接受已登记的原工作区。公开文本适配器和原始事件导入保留既有能力。路径一致是必要条件，不声称充分保证模型行为或来源当前适用。

实施：`NativeCarrierCheckpointAdapter` 要求显式绝对工作区，声明迁移不支持；`publication.stage` 在插入操作或导出文件前执行适配器可选的绑定校验。实验登记在复制工作区前拒绝不匹配，真实阶段入口在请求前复查。不解读 opaque、不改原生权限、不向模型追加纠偏提示。

回归：新增四项覆盖跨目录 stage 拒绝且零导出/零操作、同目录保留原值、未知/相对目录拒绝、真实 phase 请求前拒绝且调用次数为零。完整独立包 **111/111**，源码清单在 `../validation/native-carrier-workspace-20261023/suite-final.json`。首次测试的一个夹具漏填 origin，已补齐并保留 `suite-first.*`，未隐藏失败记录。

实际旧压缩产物只读重放：原工作区允许，失败正式组的工作区和此前成功资格的迁移工作区均拒绝；模型调用为零。回执 `actual-carrier-admission.json`。不因旧资格曾成功而为其绕过新边界，也不把执行层拒绝当成新的 B/C 收益。

该修复使旧 native-carrier 计划不能再直接登记到新目录。新的同工作区研究需要先设计稳定的工作区生命周期和成本归属，重新取得资格；本轮没有启动下一次付费调用。
