# 第二次选材何时必要：静态审查结论

本次仅阅读当前代码与已有报告，没有模型调用、实验、测试或新性能测量，也没有改变执行路径。

## 结论

第二次出现检查点、新消息、新需求或文件变更，不等于必须再次调用压缩选材模型。需要区分三件事：是否需要缩减工作集、是否需要读取旧证据、是否允许发布当前状态。

当前案例的 C2 是脚本固定安排，未先证明容量压力。它同时承担旧证据恢复，所以不能直接删除 C2 并假定原先的续接正确率仍然成立。能够复用的是原模型选择及其历史身份，不是把旧判断重新认证为当前事实。

## 代码实际怎么做

- [late_recovery_qualification.py](</D:/lea/XenYon code/wsc/benchmarks/deterministic_v1/late_recovery_qualification.py:74>) 已将完整新 delta 追加给 C1 接收器；之后第 95 行仍固定执行第二次 select/publish，没有先判断现有可见工作集是否需要缩减。
- [native_incremental_candidate.prepare](</D:/lea/XenYon code/wsc/experiments/native_incremental_candidate.py:133>) 每次都会构建 frontier 并执行 generate，没有复用/原样延续分支。这是现有显式选材 API 的行为，不能把绕过回调当成兼容修复。
- [core.prepare](</D:/lea/XenYon code/wsc/src/wsc/core.py:116>) 可以接受现成 Selection，不隐式调用模型。底层已有无生成的准备能力，但没有现成的、完整受约束的“旧选择＋新尾部”策略。
- [CodexCheckpointAdapter.render](</D:/lea/XenYon code/wsc/src/wsc/adapters/codex.py:62>) 能将边界后的尾部按原序追加，但不能据此跳过视图/发布校验。

已有原始指标：C2 前的旧视图加 delta 平均 3611 B，C2 后平均 3549 B，两个样本还增大。它没有表现出显著的字节缩减需求；C2 的平均 75135.7 Token 包含了旧来源恢复和重新选材。这不能证明所有生产会话的第二次压缩都多余，也不能只凭字节数认定宿主 Token 容量足够。

## 三类情况

|情况|适当处理|是否需要新的语义选材|
|---|---|---|
|原模型选择仍有完整来源证明，全部新增内容可原样携带，实际预算与宿主容量允许，调用方没有请求重选|保持旧帧、原样追加完整新尾部，保留时间顺序和选择来源|不因新增内容自动要求一次额外选材|
|全部保留后超出真实容量，需要决定舍弃、改写、合并或改变保留范围|由模型或调用方明确作出语义选择|需要语义决策；不能由引擎按关键词裁剪|
|模型/用户明确请求重新组织或修订工作理解，即使容量足够|执行该明确决策，不静默当成无事发生|按请求进行；不能因字节小而拒绝重选|
|只缺某个历史值、证据或版本观察，当前工作集仍可容纳|正常任务模型按需恢复原文/观察|需要补证，不必因此重做整个工作集|
|源摘要/视图哈希、身份、权限、发布状态或工具边界不成立|拒绝、报告事实状态或走恢复流程|不能把坏绑定交给模型“修补”|
|理解记录、引用或外部文件发生变化|先核对变化对象和适用边界；必要信息可完整追加则保留原始变化，不能确定时交调用方决策|全局 epoch 变化本身不是语义重选充分条件，也不能无条件复用|

“调用方决策”不等于引擎自动追加一次 LLM 请求。引擎可以返回无法无损延续的事实原因，由调用方选择继续、恢复或重选。

## 允许机械续接的完整条件

1. **旧选择真实且完整**：校验 session/workspace、旧 source cut/digest、视图 body digest、所选来源、理解精确 revision、clue 来源和 excerpt 范围/hash。不能只比较记录数量或 excerpt key 集合。
2. **旧判断保留历史身份**：沿用旧原文和选择内容，不重写旧 clue，不自动升级到最新理解 revision，不把测试 V1 的依据变成测试 V2 的依据。新的观察边界与旧的语义选择边界必须分开记录。
3. **增量完整**：保留全部新增原始内容，不只挑 user 或看似重要的消息；同时核对事件尾部之外的理解/引用/发布状态变化。不能把事件 cut 没变当成整个工作状态没变。
4. **先旧后新**：旧帧作为旧帧出现，完整新尾部在后面。当前普通 adapter 先发全部 message 来源、再发 working_state；若简单把新来源合入旧 body，旧 clue 可能出现在新消息之后。需要专门处理顺序，不能只做 source_ids 的并集。
5. **真实容量通过**：内部 prepared-view 字节、适配器水合后的 rendered bytes、宿主实际 Context 与输出预留都要满足。小于 49152 B 不等于已证明提供方 Token 容量充足。
6. **新绑定与原发布规则**：需要发布时，用当前合法 snapshot 建立新视图和操作。旧视图 control_epoch/generation 过期会被现有校验拒绝；不能把字段改成新值或绕过校验来复用旧安装。
7. **恢复可达**：普通续接模型具有可用、计费明确的历史恢复通路。原始归档存在不等于实际恢复能力已经交付到该模型。
8. **不透明内容和未完成工具保持边界**：不能丢掉 opaque、截断调用/结果或伪造已消费回执。宿主不能原样承载时返回不支持/需要恢复；不能让模型猜原始密文或缺失结果。

理解 epoch 是粗粒度变更信号。它可能来自无关记录，不能直接强制全量重选；但只拿旧 selected refs 去比当前所有 refs，也不能可靠恢复增量，因为“之前未选”不等于“后来新写”。需要有绑定的旧记录清单或实际变化记录。证据不足时不能假装已获得完整变化集。

## 现在为什么不能直接删掉 C2

[LateCell.new](</D:/lea/XenYon code/wsc/benchmarks/deterministic_v1/late_recovery_qualification.py:33>) 只为 selector 创建带 WSCSource 的线程；[probe](</D:/lea/XenYon code/wsc/benchmarks/deterministic_v1/blackbox_group_runner.py:114>) 的普通后测没有该专用 handler。它仍有普通原生工具和冷索引路径，但不能假定具有同样方便、同样成本的恢复能力。

这个案例需要旧 nonce，C1 没有把它直接留在帧里。当前 C2 提前取回并选入 nonce，后测才一次答对。若跳过 C2，证据读取仍需发生，成本可能转移到任务模型，恢复是否成功也尚未证明。不能把 75135.7 Token 全部当作可确定省下的成本，更不能沿用原 6/6 宣称删 C2 后仍然正确。

已有 native_message_checkpoint 是首轮按类型保留消息/观察的旧旁路，不是复用原模型选择的第二轮续接；直接套用会改变保留策略和预算条件，不采用这种替换。

## 发现的一个相关完整性缺口

frontier 读取旧 view 时直接 SELECT＋json.loads，然后检查 cut、source digest、理解 ref 列表和 excerpt key 集合；没有调用统一的 [view_record](</D:/lea/XenYon code/wsc/src/wsc/snapshots.py:30>) 来检查 body digest。

因此静态上存在旧 clue 内容改变、其余这些字段不变而进入选材输入的路径。现有字段比对不足以证明旧模型选择未变。此处是静态发现，未运行篡改复现；不能标成“已实验确认”。无论继续选材还是未来复用，旧视图完整性都应先验证，失败时拒绝而不是让模型修补。依照本轮范围，未修改源码或运行测试。

## 收敛后的方向

现有 generate/prepare 的显式语义选择含义保持。未来若实施，机械续接是独立入口或旁路，输出旧选择来源、完整增量范围、容量与绑定事实；不能伪称进行了第二次模型选材，也不能偷偷改变原固定两检查点评测条件。

先解决旧选择完整性、变化覆盖、呈现顺序和正常续接恢复接口，再谈是否省掉某次调用。当前只确定了必要条件和代码缺口，没有实现新策略、没有实验或新的正确率/速度结论。原生 B 不变，不重启 native-plus-R/M。
