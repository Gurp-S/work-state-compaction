# 公开的应用交付复核程序

外部评审对每条最终轨迹按同一程序执行，先保留提交文件清单、启动命令、数据和自动回执，再打开应用。展示编号随机化，评分记录不显示B/C身份；如果评审人员已看见轨迹或身份，则标明未实现盲评。评分使用experiments/BC-UI-REVIEW-RUBRIC.md的6维24分量表；功能与数据错误独立记录，不以视觉分抵消。所有需求和检查程序在首次模型调用前公开。

逐项记录 `pass/fail/unknown`、要求所在TASK.md阶段、当前源码哈希、具体操作、请求响应或截图路径和原因。没有执行的项为unknown。最终资格要求：累计自动检查完成并通过，以下适用人工项有证据且通过，没有未处置的关键错误；运行/评审预算用尽计实际未完成，不由评审者代修产物。验收驱动故障与被测应用失败分别记录。评审不能凭报告里的“已验证”当作执行证据。

共同界面项目：

- 使用真实服务端数据完成创建→列表→筛选→详情→修改→刷新→重启后读取；核对页面、服务端和导出同一对象身份。切换admin/member/viewer/另一租户，记录权限及错误反馈。
- 在1440、1024、390宽度和明暗主题分别保存首屏截图；至少另存详情、空态、失败、加载中和大数据截图。无意外全页横向溢出，表格允许局部滚动；长名称不遮住主要操作。
- 使用键盘完成任务主要操作，记录焦点可见、可访问名称、确认/取消路径。用户文本含 `<img src=x onerror=...>` 时以文本显示，不执行HTML。
- 1000项数据下记录加载、筛选、分页和切换实测耗时及机器/并发条件；不能把开发服务器冷启动算成单次交互耗时。验收运行器不提供充分的性能证明。
- 反复修改筛选/日期/详情，受控延迟一个旧请求后切换到新对象，检查旧响应不覆盖新状态。刷新失败可看见失败与旧数据状态，重试有反馈。

分任务补充：

| 任务 | 复核操作与结果 |
| --- | --- |
| collaboration | 自定义流转后拒绝删除仍被使用的状态；评论作者来自身份而非输入。跨两页搜索和同筛选导出核对无重复漏项；只对选中工单批量操作。故障批次和失败撤销无部分写入，对应成功审计与状态一起持久化。并发冲突页面保留未提交内容，重新载入不会偷偷提交。 |
| files | 从浏览器真实选择文件、暂停和续传、下载后核对SHA256。旧版本下载和标签分页正常；恶意folder、非法base64和hash不符均不发布文件。旧v1 welcome迁移后字节与id不变，多次启动不重置。分享在删除、恢复、撤销及重启后按合同失效；清理保留当前和历史引用内容。 |
| imports | 从文件选择到原文预览、修正映射、排队、执行、取消和导出都可操作。CSV引号换行定位原物理行；未知金额保留null。排队旧映射不随UI默认改变；取消与run并发不会同时取消又提交，进程在提交中止后无半批数据。分页与同筛选聚合/导出集合相同。 |
| booking | 日历和日程列表能创建、改期和取消；相同绝对时刻不同offset、跨日与无offset输入按合同处理。修改资源时区前后绝对承诺不漂移；改期后的旧版本通知不再发送。降权页面重试被拒绝，重复预约修改范围可见。导入一条冲突导致全批不创建；v1预约幂等迁移、重启和投递去重。 |

S8复核文档与源码：README中的命令在独立环境实际启动；依赖、已知限制、数据目录和迁移说明准确。代码不存在仅针对验收样本值/路径/测试名称的特殊处理，未修改外部验收或伪造回执。需要崩溃边界证据时记录实际终止位置与重启后数据，而不以正常restart替代崩溃恢复证明。当前HTTP校准后端是作者测试材料，不能作为模型交付、生产实现或完整应用参考答案分发。
