# 四个独立应用任务的共同交付合同

这是 application-five-task-v1 中 collaboration/files/imports/booking 的公开任务说明。A3 使用自己的现有项目与合同。四个应用各自从 starter 独立开始，不共享实现、数据库或运行历史。所有阶段要求和验收源码从首次调用就共同可见，S1-S8 是分段交付顺序，不是事后隐藏要求。各任务均完整执行三组 B/C；阶段数不算重复数。

交付可实际操作的完整应用：清楚的导航、精致一致的布局、1440/1024/390 宽度、明暗主题、可见键盘焦点、加载/空/失败/成功反馈。列表、筛选、详情、编辑和危险操作确认须真正调用服务端。静态假数据、只实现 API、截图中有按钮但不能操作，均不构成合格交付。首屏可识别当前身份与数据范围。用户输入以文本显示，不能执行其中的 HTML。运行在本机，不发送真实邮件、不连接外部业务服务。

起点是可运行但功能有限的 Python 标准库 HTTP 服务和网页。可以拆分模块或更换内部实现，保留启动入口 `python -B -X utf8 -m backend.server --data ABSOLUTE_DIR --port 0`；stdout 输出一行 JSON `{"ready":true,"port":实际端口}`。`GET /api/health` 返回 200 和 `ok:true`，`GET /` 提供应用。所有可变持久化数据在 --data 内；源码目录、其他轨迹和外部应用不可作为数据库。进程被终止后重新启动同一 data 目录，已提交的业务状态仍有效。需要新增依赖时必须列清版本与离线启动方法。

公开 API 使用 JSON，错误为非 2xx 和 `{error:字符串}`，列表 `{items:数组}`，资源返回对象本身，id 为稳定非空字符串。未列出的响应字段可扩展。POST 创建返回 201，幂等重放返回 200，PATCH/DELETE/显式动作成功返回 200；非法数据 400，内容校验失败 422，版本/业务冲突 409。缺失/未知 token 401，已登录无写权限 403，跨租户或不可见资源 404。版本从 1 起，每次成功变更加 1，失败操作不变。并发检查与写入须为一次原子操作。健康检查、页面和公开分享例外，其他 `/api/` 默认要求 `Authorization: Bearer TOKEN`。

演示身份是固定公开测试数据：`admin-a`、`member-a`、`viewer-a` 属 tenant-a；`admin-b` 属 tenant-b。admin 管理成员；member 读写业务；viewer 只读。`PATCH /api/members/member-a` 的 `{role:"viewer"}` 立即使旧 token 的后续写入失效，并在重启后保留。此身份机制只用于本地任务，不表示生产认证已经交付。UI 提供具名“当前身份”选择器。

每阶段提供实际修改、执行证据、尚未通过的项。S8 提供 README、启动方式、迁移与恢复说明、已知限制以及截图。验收从外部可信副本运行，模型不能通过改验收器、改回执、跳过失败项取得合格。已有回执只绑定当时的源码。公开自动检查是部分覆盖：漂亮程度、完整操作路径、键盘可用性、异常显示、性能及源代码审查另记，不把 API 通过当整个应用合格。

本目录当前是实验准备材料。模型、候选 WSC、边界和预算仍以最终实验登记为准；此文件不授权绕过准入启动。各阶段累计保留此前要求，除非该任务明确写出兼容变更。
